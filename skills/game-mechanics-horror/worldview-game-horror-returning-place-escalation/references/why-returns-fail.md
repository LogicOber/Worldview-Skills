# Why returning places fail

## Same map, darker
Lighting can support a state change but cannot replace one. Change a question, action, permission, route, relationship, threat rule, or interpretation.

## Every landmark disappears
Without stable grammar the player sees a different room, not a meaningful return. Preserve functional anchors across presentation changes.

## Approximate callbacks replace shared IDs
A similar chair or door cannot carry custody, damage, or witness history. Reuse the same authoritative ID when causality depends on sameness.

## A return exists only to fetch a collectible
The place becomes transit. Give the player a comparison action and a changed consequence, or merge the traversal.

## Random prop rearrangement
If many objects change without cause, no rule can be inferred. Change one primary fact, preserve anchors, and leave residue.

## Arbitrary blockers force a detour
A closed door without visible state or cause teaches that the author can revoke routes at will. Tie route changes to object, permission, damage, pressure, or threat state.

## A new viewpoint knows everything
Track observer-specific knowledge and inspected evidence. A shared place is not a shared mind.

## Presentation becomes truth
Darkness, a label, or a voice may lie. Load authoritative state first and let presentation read it.

## Occupants teleport with no schedule or residue
Record last verified location, legal movement, custody changes, and the consequence of absence.

## Every return is more hostile
Without interpretive or recovery returns, escalation becomes fatigue. Some visits should grant knowledge, route control, or relationship clarity.

## Wrong interpretation soft-locks the place
A fair return preserves an anchor or recovery edge. Failure should refine the comparison rather than erase access to it.

## Final return introduces a new solution
Pay off an earlier landmark, object, route, or relationship using a learned verb. Do not solve the place with an unseen mechanic.

## Minimal acceptance test
A player recognizes the place, names the stable anchors, identifies an exact change, tests it through action, receives a state consequence, recovers from a wrong reading, reloads consistently, and uses an early anchor at payoff.
