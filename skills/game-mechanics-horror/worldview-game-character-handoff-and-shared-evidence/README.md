# Character Handoff and Shared Evidence

Use this Skill when a single-player game changes playable protagonists and the same event, place, object, or consequence must remain authoritative across viewpoints.

```text
/worldview-game-character-handoff-and-shared-evidence

Three playable responders enter the same flooded archive at different times.
Earlier actions must become later physical evidence. Each responder knows only
what they personally observed or received. Keep one ending and make every
switch, save, failure, and skipped scene preserve ownership correctly.
```

The Skill separates four records that are often accidentally merged:

- what actually happened;
- who physically holds or changed something;
- who knows or believes each fact;
- how the current viewpoint presents that truth.

It produces a domain-owner map, shared-ID registry, cross-viewpoint handoff ledger, consequence rules, viewpoint-switch transaction, save/recovery policy, convergence gate, implementation plan, and verification journeys. It can implement the system when an authorized runtime is available.

Do not use it merely because a story has several named characters. Use it when at least two playable viewpoints inspect or alter shared state and the order of actions must remain causally exact.

- Use asymmetric-information cooperation for live communication between simultaneous roles.

This Skill owns cross-viewpoint indexing, residue mapping, transaction order, and transition integrity. World truth, physical custody, actor knowledge, presentation, permissions, and ending state remain with their domain owners; the handoff ledger stores stable pointers and committed versions rather than redefining them.
