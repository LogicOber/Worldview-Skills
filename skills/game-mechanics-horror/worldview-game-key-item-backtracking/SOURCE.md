The Skill begins from a general design problem: revisiting space becomes meaningful when a protected capability changes reachability and the return asks the player to recognize, reinterpret, or choose within an already learned map. It does not reproduce any published lock, key, route, enemy, or story sequence.

## Repository writing method

The structure follows the user's supplied Writing 2 principles without reproducing its text. The problem appears before the rule; project facts, runtime observations, and new proposals remain distinct; reasons and counterexamples travel with constraints; verification supports rather than precedes conclusions.

## New design decisions

This Skill introduces:

- the public invocation `/worldview-game-key-item-backtracking`;
- four default route snapshots from initial block to durable unlock;
- a requirement that return changes have visible causes;
- protected, atomic key acquisition and application;
- measured wrong-turn and shortcut costs;
- optional reminders that repeat known facts without revealing solutions;
- save migration, accessibility, and multiplayer authority boundaries;
- the default four-file handoff under `gameplay/<return-route-slug>/`;
- the fictional Rain Archive example.

These are repository proposals, not claims about every horror or exploration game. Projects may use different state names or document locations if they preserve the same responsibilities.

## Independence from sibling mechanics

The Skill can be loaded and applied alone. It may share a project with inventory scarcity, pursuit, treatment, or limited saving, but none is an installation dependency. When combined, the gate's protected state and recovery path remain explicit instead of being delegated implicitly to another Skill.
