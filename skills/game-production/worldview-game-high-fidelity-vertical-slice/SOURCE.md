# Source and Originality Record

## Repository authorship

`worldview-game-high-fidelity-vertical-slice` is an original production method written for Worldview Skills. It turns a short creative premise into a bounded playable slice, protects the playable spine before expensive art work, separates runtime behavior from visual evidence, and requires truthful verification before delivery.

Its lock order, project-recovery procedure, state-coverage model, representation decisions, asset and rights ledger, causal visual passes, performance evidence, external-tool boundaries, fillable contract, reference material, and fictional example were authored for this repository.

## Research boundary

The user supplied private observations about model-assisted game production and the gap between an impressive still image and a complete playable result. Those observations established the problem to solve. They are not public dependencies and are not reproduced, cited, summarized scene by scene, or shipped with this package.

No external Skill, repository structure, code, prompt, workflow tree, example, game fiction, visual identity, asset, screenshot, model, texture, audio, script, test, schema, threshold, or provider integration is included or adapted here.

Official product documentation may be consulted at use time for factual model, API, or tool capabilities. Those changing facts do not supply this package's method or expression.

## Original method boundary

This package independently owns:

- story-first intake and reversible assumptions;
- a playable-spine contract for input, camera, traversal, interaction, failure, reset, and persistence;
- three to five reachable runtime states instead of one beauty frame;
- one visual grammar across form, material, light, color, motion, lens, interface, and sound;
- representation selection per content family;
- grey-box and proxy proof before expensive asset production;
- causal fidelity passes tied to named gameplay states;
- separate behavioral, visual, temporal, rights, and performance evidence;
- explicit authorization and fallback rules for image tools, DCCs, MCP servers, APIs, stores, and deployment;
- editable-source and runtime-export acceptance;
- a truthful handoff that distinguishes implemented, proposed, measured, and unverified work.

## Non-copy declaration

All prose, tables, templates, examples, names, values, routes, and verification rules in this package were written for Worldview Skills. The fictional Glass Tide Station example is newly authored and is not a representation of an external game.

Future revisions must preserve this boundary: private research can identify a production problem, but public methods and examples must be independently designed, provider-neutral where possible, and verified against the user's actual project.
