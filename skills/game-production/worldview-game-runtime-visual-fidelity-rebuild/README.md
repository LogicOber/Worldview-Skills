# Worldview Game — Runtime Visual Fidelity Rebuild

Turn a mechanically complete but visibly provisional game into a coherent runtime experience without quietly redesigning how it plays.

This Skill is for the difficult middle ground between “the game works” and “the game looks authored.” It addresses default primitives, flat vectors, generic lights, stock interface surfaces, weak motion and audio feedback, and asset-pack collage. It does not treat a polished screenshot as success. The finished build must preserve the locked game, improve the ordinary play view as well as hero moments, remain lawful to ship, and carry measured runtime evidence.

## Use the Slash command

```text
/worldview-game-runtime-visual-fidelity-rebuild

The game at <repository path> is playable through <entry point>, but its
runtime still looks provisional because <observed problems>. Preserve
<mechanics, timing, routes, collision, authority, saves, and accessibility
behavior>. Build a coherent presentation around <owned references or written
direction>. Verify <three to five named states> before and after. The target
platforms are <platforms>, and external tools are authorized only as follows:
<DCC, image, audio, cost, privacy, and file-scope limits>.
```

The Agent should return an implemented rebuild when repository and runtime access exist. A restated prompt, mood board, isolated concept image, or attractive DCC render is not the deliverable.

## Use it when

- A playable route already exists and should remain mechanically stable.
- Placeholder or generic presentation dominates the real play view.
- Several individually attractive assets fail to read as one world.
- A visual direction exists but has not reached materials, lighting, motion, UI, audio, loading, failure, and recovery states.
- A previous polish pass improved one capture without proving performance or regression safety.

Do not use it to invent a game from nothing, rebalance systems, restructure levels, produce only marketing media, or imitate another game’s protected identity. If the request is a new bounded playable experience, `/worldview-game-high-fidelity-vertical-slice` may be useful, but this package does not require it.

## What the Skill produces

The work is organized around evidence rather than a vague request to “make it cinematic.” Expected outputs are:

1. A baseline tied to the exact project revision, run command, platform, renderer, viewport, quality settings, and accessibility state.
2. Three to five named runtime states that can be reached again under recorded conditions.
3. A protected-behavior contract for inputs, timing, collision, route topology, AI, objectives, economy, RNG, camera duties, saves, network authority, and accessibility behavior.
4. A causal diagnosis that separates observations, proposals, and judgments.
5. A production route and rights record for each geometry, illustration, material, effect, interface, and audio family.
6. Integrated presentation passes across the families the evidence actually requires.
7. Same-state baseline/final comparisons, frame-time evidence, real regression journeys, and a truthful list of unverified claims.

## The six dependent locks

The rebuild uses six locks in this order:

1. **Protected Behavior Lock** — records what the art pass may not change.
2. **Baseline State Lock** — fixes the three to five runtime moments and their comparison conditions.
3. **Causal Fidelity Lock** — connects visible symptoms to falsifiable causes.
4. **Production and Rights Lock** — authorizes how each content family is made and establishes whether it may ship.
5. **Calibration Lock** — accepts only presentation rules that hold across the named states.
6. **Runtime Proof Lock** — binds final claims to regression, accessibility, persistence, authority, and performance evidence.

A reopened early lock invalidates dependent work. For example, changing the camera’s gameplay duty reopens the Protected Behavior Lock and invalidates later comparisons; changing the viewport or seed reopens the Baseline State Lock; replacing a texture source reopens its rights row and invalidates captures that contain it.

## Tool use is conditional

The Skill can coordinate a repository, running game, browser or engine capture surface, image API, Blender MCP, local DCC, audio route, and profiler. It does not assume any of them are connected or authorized.

- Image generation requires an allowed purpose, input rights, cost boundary, and storage rule. A written visual grammar and owned references are the fallback.
- Blender MCP requires an explicit connection plus allowed scene, file, save, and export scope. Authorized local Blender, another DCC, project-native construction, or a labeled proxy are fallbacks.
- A DCC render is evidence about an editable source, not evidence that the runtime export loads or performs.
- Unknown asset rights cause quarantine. They never become “probably safe” because a deadline is near.
- Missing profiling access narrows performance claims; it does not justify invented measurements.

## Model recommendation

Use `gpt-6-astra` when available. **Max** is the deeper single-agent choice for a tightly coupled rebuild. **Codex Ultra** is orchestration: it can delegate genuinely independent production and verification tracks while a lead owns the locks and integration. In the API, request model `gpt-6-astra` with `reasoning.effort: "max"`; `ultra` is not an API effort value.

The package remains usable with another capable model. Model choice never replaces runtime observation or proof.

## What a good handoff says

A useful handoff identifies the exact revision and entry point; the protected fields; all named states; the source and runtime form of changed assets; external tools actually used; same-state captures; representative and stress measurements; regression journeys; save, accessibility, and network results when applicable; and every remaining proxy, unsupported platform, rights question, or unverified claim.

“Looks production-ready” is a judgment. “The recorded pressure state retained the same objective, collision contacts, target IDs, and input result while its measured frame interval changed under these conditions” is evidence. The Skill keeps both kinds of statement legible.
