## 8. Verification

- [ ] A new player can state the immediate objective without reading hidden design notes.
- [ ] The first failure has a visible cause and a faster retry.
- [ ] Every selected mechanic has a working state, feedback, reset, and fallback.
- [ ] Each chase or pursuit has a legal architectural route, not only enemy following.
- [ ] Returning spaces change an object, relationship, route, lighting state, or threat rule.
- [ ] Audio, camera, lighting, and UI cues are recorded as player-facing evidence.
- [ ] Save/load, death, restart, checkpoint, and ending states were tested.
- [ ] Accessibility paths preserve the decision even when intensity is reduced.
- [ ] Every runtime, performance, asset, and deployment claim points to evidence.
