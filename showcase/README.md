## One project, one folder

```text
showcase/
├── README.md
├── TEMPLATE.md
└── creator-project-name/
    ├── showcase.md       required; demo video first, then project details
    └── assets/           optional screenshots and small supporting files
```

Each project page starts with its actual demo video, before the title or other text. Include the creator, a short description, the Skills used and how they helped, and any available play/watch/read or source links. Label concept footage and prototypes honestly.

Use a video attachment or public video host instead of committing large video files. A GitHub-uploaded video URL on its own line is preferred; check that the rendered page plays it. If a host only supports linking, put a clickable video preview first and label it “Watch the demo.” A still image without a working video destination is not enough. Check accessibility to readers outside your account; private-repository attachments may require access.

See [GitHub's attachment instructions](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/attaching-files) for supported uploads. Do not invent attachment URLs or claim an untested link works.

## Featured selections

Maintainers choose a small selection for the English and Chinese READMEs and may refresh it weekly as submissions arrive. Each feature contains the demo video or linked preview, project title, creator credit, and a link to its `showcase.md`. Reuse the submitted media rather than duplicating it in Git. Being accepted does not guarantee homepage placement.

Older selections remain in this directory and its index. Contributors should update their own project folder when improving an existing submission, rather than adding a duplicate.
